# macOS computer use 演练记录

日期：2026-10-07，北京时间。环境：macOS、飞书桌面 App，英文界面；Chrome 已登录飞书开放平台。此记录区分实际界面观察、离线脚本验证和尚未执行的步骤。

## 已实际走过的界面

1. 用 computer use 检查可用应用与浏览器，确认飞书 App 已登录。
2. 进入现有“Codex通知”群，观察已有的任务通知机器人。
3. 通过右上角“⋯”→`Settings`→`Bots`→`Add Bot` 打开机器人列表。
4. 选择 `Custom Bot`，确认创建表单只要求头像、名称和描述，不要求申请企业自建应用。
5. 用户选择新建测试群和机器人，并允许一条测试消息。退出现有群的创建表单。
6. 从左上角 `New`→创建群进入 `New Group`。保持 `Chat` 类型，填写“Codex通知配置测试”，不选择其他成员，点击 `Create`。
7. 群界面显示正确名称、1 名成员和创建记录，确认测试群已创建。
8. 在测试群中重复 `Settings`→`Bots`→`Add Bot`→`Custom Bot`。
9. 将名称填写为“Codex通知配置测试机器人”，描述填写为单向通知配置演练用途。

## 演练停止点

**尚未点击创建机器人的 `Add` 按钮。** 当前 computer use 工具要求在创建持久凭据的实际步骤确认；已向用户展示机器人名称、目标测试群和本机配置路径，并等待现场确认。

因此本次记录尚不证明机器人已入群、签名设置已保存、剪贴板凭据捕获或一条真实测试通知到达。后续演练配置将保存到仓库外的 `~/.config/codex/feishu-notify/setup-test.json`，避免覆盖已有通知群配置。获确认后继续创建、获取 Webhook、开启签名、保存本机配置及确认测试消息。

## 已完成的本机验证

- 在 Python 3.12 下通过 9 项离线测试，未向飞书发送任何消息。
- 通过 Codex skill 格式校验。
- 验证完整配置写入的密钥不会出现在 stdout／stderr，文件权限为 `0600`。
- 验证已有配置不会被隐式覆盖，剪贴板逐字段配置保持禁用，完整凭据保存后才能启用。
- 验证 Webhook 域名限制、禁止重定向、签名请求及超时不自动重试。
- 验证安装只复制 skill 资源，替换时备份旧版本。
- 安装新 skill 后，既有“Codex通知”配置离线状态为 ready；离线预览确认使用签名 Webhook，不依赖桥接服务。
