# 给 Codex 的 computer use 配置引导

用户明确要求安装或配置时执行本流程。目标是本机 skill 已安装、凭据安全保存、签名 Webhook 可发送，并在用户指定的群里确认一条测试消息。可以按已有配置从中间继续，避免重复建群和机器人。

## 1. 检查环境与授权

1. 阅读 SKILL.md；从仓库开始时再读 README.md。本引导也适用于已安装的 skill，确认当前版本只做单向通知。
2. 用终端检查 Python 3.10+，执行 `python3 scripts/configure.py status`。状态脚本不打印密钥；不要 `cat` 真实配置。
3. 在执行安装、建群、创建机器人、修改配置或发送测试之前，合并询问下表中尚未明确的问题。等待回答，默认建议不会因用户未回答而生效。可以继续必要的只读检查；不能用等待时间结束来替代用户选择。
4. 当前会话已明确的选择和授权直接复用。已有有效配置时，先确认本次是复用、只测试还是重新配置。用户回答清楚后按相同范围继续，不另加重复的整体确认；当前工具要求的现场确认仍在相应步骤处理。
5. 使用当前提供的 computer use 工具查看可用浏览器及飞书 App，先读取其操作文档。各宿主的权限规则仍适用：例如创建持久凭据若要求现场确认，在真正点击创建前遵守该要求。不因用户阅读 README 就发送消息。

| 执行前问题 | 询问方式与建议 |
| --- | --- |
| 飞书账号与组织 | 有多个账号或身份不明确时询问；已明确则跳过 |
| 群的选择与名称 | “使用已有群还是新建群？群名是什么？”新建可建议“Codex通知”，只保留用户自己，不邀请其他联系人 |
| 机器人的选择与名称 | “复用该群已有的自定义机器人还是新建？机器人名是什么？”新建可建议“Codex任务通知” |
| 描述与头像 | “使用默认描述和头像，还是有自定义要求？”默认可用任务结果摘要说明和飞书默认头像 |
| 一条配置测试消息 | “配置好后，是否允许向选定群发送一条测试消息？”只做离线检查时跳过实际发送 |

先收集群与机器人选择，再准备相应表单。名称必须使用用户的回答或用户明确接受的建议；复用已有群或机器人不代表授权重命名。确认项较多时一次展示，避免每执行一个普通步骤都问一遍。不要向用户索取密钥到聊天中。

## 2. 安装与登录

- 飞书 App 已安装且登录：直接操作 App；不要求重复登录开发者后台。
- 未安装：引导用户访问飞书官方下载页，按用户授权安装；安装权限不足时说明需要的具体一步。避免来源不明的安装包。
- App 未登录：显示登录页面，请用户扫码或完成验证码。不要索取账户密码到聊天，遇到协议接受、验证码或工具要求人工操作时交给用户。
- 只有浏览器：检查飞书网页版可用的群设置入口；没有入口就指导用户安装官方桌面 App或使用客户端手工创建。不要猜测一条未经确认的 Web 路径。
- 没有 computer use：继续安装及配置工具，把剩余的群和机器人界面步骤交给用户，明确哪些步骤尚未验证。

## 3. 创建或进入通知群

已存在指定群则复用。新建时，从飞书左上“＋／New”进入“创建群／New Group”，选择普通聊天群，填写用户指定名称，成员只保留自己，点击创建。界面应出现正确的群名和创建记录。

不要把开发者后台的“创建企业自建应用”当成此步骤。单向通知使用群内自定义机器人，群创建后即可直接申请并入群。

## 4. 申请机器人并入群

1. 当前群右上“⋯”→“设置／Settings”。
2. 打开“群机器人／Bots”→“添加机器人／Add Bot”。
3. 选择“自定义机器人／Custom Bot”，不要选择企业自建应用机器人。
4. 填写名称及描述，使用默认头像即可。实际操作时从新观察的状态取得控件，不硬编码本次机器的坐标或元素编号。
5. 按当前工具的确认要求点击“添加／Add”。自定义机器人会立即加入当前群，并显示配置页；它不需要邀请审批或发布应用版本。
6. 确认群机器人列表或群系统记录中出现正确的机器人。界面异步加载时先观察，不因按钮暂时无变化而重复创建。

## 5. 签名设置与密钥保存

打开新机器人配置，启用“签名校验／Signature Verification”。保留其他已存在的安全策略；机器人新建场景选择签名校验即可。不要重置已有机器人的密钥，除非用户明确要求。

真实配置必须在仓库外。默认 `~/.config/codex/feishu-notify/config.json`；配置演练另用用户配置目录中的 `setup-test.json`，每条命令均显式加 `--config`，避免覆盖原通知群。

优先点击界面的复制按钮，由配置脚本读取本机剪贴板，勿在工具返回中显示 Webhook 或签名密钥：

```sh
# 界面复制 Webhook 后
python3 scripts/configure.py capture webhook --group-name 'Codex通知'
# 界面复制签名密钥后
python3 scripts/configure.py capture secret
python3 scripts/configure.py enable
python3 scripts/configure.py status
```

自定义路径示例：`python3 scripts/configure.py --config ~/.config/codex/feishu-notify/setup-test.json capture webhook --group-name 'Codex通知配置测试'`；后续 capture、enable、status 和 send 也使用该路径。

看到密钥界面时避免将原始 accessibility tree 或截图输出到会话；可在工具允许范围内使用不输出原始结果的观察，再对凭据字段及包含 Webhook 的 URL 做遮蔽。只输出控件名称、类型、状态和供操作的索引。遮蔽后的信息必须足以决定下一步；无法安全观察时让用户复制并通过本机隐藏输入写入。

`capture` 会保持 disabled，随后 `enable` 才进行完整校验。`--replace` 仅用于用户明确要求修改现有已启用配置的情况。完整 JSON 的自动输入可用 `configure.py write --stdin`，但不要把真实 JSON 写成显示在聊天里的 shell heredoc或临时仓库文件。

浏览器和桌面 App 的剪贴板可能不是同一个；仅在具备同一系统剪贴板时使用上述 capture。不要打印剪贴板做调试。复制按钮不适用时使用本机 `configure.py write` 隐藏输入。

在飞书界面完成保存按钮（如存在）后，确认签名校验已启用。不要把本地 `enable` 误认为飞书界面也已保存。

## 6. 安装 skill

已从安装目录调用本 skill 时跳过安装。首次从仓库开始，在仓库根目录运行 `python3 scripts/install.py`。已有 skill 时，按用户更新请求用 `--replace` 备份后替换。安装器自动复用已有目录／符号链接，避免安装两份同名 skill。只有脚本和指导文件进入安装目录，密钥依然位于本机用户配置目录。

如只要求设置而没有要求安装，可以从仓库直接运行，但应告知后续聊天尚未自动发现该 skill。

## 7. 验证通知到达

1. `configure.py status` 确认 ready，文件权限在 macOS/Linux 为 0600。
2. 用 `send.py --dry-run` 离线检查目标群和消息，消息只包含非敏感测试说明。
3. 用户授权发送测试后，运行一次实际发送。返回 `accepted: true` 是接口接受；通过 computer use 返回指定群，看到标题与摘要一致的消息才证明到达。
4. 检查群名和机器人名正确。HTTP 失败或超时不自动重试；先查看群聊，必要时说明错误码，并等用户明确要求重试。
5. 若用户要手机推送，让用户在手机确认提醒。桌面看到群消息不等于手机弹出了通知。

最终说明已完成的步骤、实际群名、本机配置路径、测试是否在群中确认、安装位置以及用户之后可以说的触发句。不要输出任何密钥。未经实机验证的路径必须明确标注；不要把文档步骤描述成已完成。
